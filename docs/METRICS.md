# Metrics

All numbers are regenerated by the scripts in `guardrail/evals/`. Latency is
machine-dependent — rerun on the target machine before quoting it.

## Constraint engine — `guardrail/evals/run_golden.py`

Evaluated against the labelled dataset (2,313 rows, all 7 outcomes).

| | Result | Target |
|---|---|---|
| outcome accuracy | **2313 / 2313 = 100%** | reproduce the workbook exactly |
| gate latency p50 / p95 / p99 | 0.03 / 0.08 / **~0.1 ms** | ≤ 5 ms p99 |

Proves: all 109 conditions parse, the workbook loads fail-closed, the three

> Caveat: the labelled dataset is `reviewed = 0`. 100% means "matches the label";

> frozen test set below reduces this risk for classification; outcomes still rest

## Intent classifier — `guardrail/evals/run_t2.py`, `run_frozen.py`

Measured on the **frozen independent test set** (530 rows), which was generated
from a spec by a separate process with no access to this codebase — so there is
no train/test leakage. Trained candidates train on the labelled pool (2,313
rows) and are scored only on the frozen set.

| Classifier | all | positive | hard-neg | infer | deps |
|---|---|---|---|---|---|
| keyword (Aho-Corasick, untrained) | 53.4% | 58.3% | 34.0% | ~0.01 ms | `pyahocorasick` |
| **TF-IDF (char2-5 + word1-2) + LinearSVC** | **88.3%** | **91.0%** | 77.4% | ~1 ms | `scikit-learn` |
| TF-IDF char-only + LinearSVC | 87.0% | 90.1% | 74.5% | ~1 ms | `scikit-learn` |
| TF-IDF + LogisticRegression | 87.4% | 90.3% | 75.5% | ~1 ms | `scikit-learn` |
| PhoBERT embedding + LinearSVC | 79.2% | 80.2% | 75.5% | ~7 ms (GPU) | `torch` + `transformers` + `pyvi`, ~500 MB |

**Chosen: TF-IDF `char2-5 + word1-2 + LinearSVC`, no abstain, primary.** ~9
points better than the embedding baseline on the independent set, lighter, and
faster. The embedding model loses because it is a general similarity model: its
confusions pile up on `đèn pha ↔ đèn cốt` and `xi-nhan trái ↔ phải` — near in
meaning, different intents — which char n-grams separate directly.

Remaining TF-IDF errors cluster on question ↔ command pairs
(`lock_doors` ↔ `get_door_lock_status`, `shift_gear_park` ↔ `get_gear`) — real
semantic ambiguity that more labelled samples or a light post-rule could close.

The keyword baseline is kept only to show the frozen set is a valid measure: it
scores the frozen set (53.4%) the same as the labelled pool (~58%), so the
frozen set is not inflated.
